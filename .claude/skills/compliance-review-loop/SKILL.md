# コンプライアンス・レビューループ

`estate-builder`（実装者）と `estate-reviewer`（レビュー役）を別々のサブエージェントコンテキストで交互に起動し、成果物をレビュー済みの状態へ収束させる。

## 手順

### ラウンド k（最大2ラウンド）

1. **Builder ラウンド** — `estate-builder` を起動する。
   - k = 1: ユーザー要求（原文）と対象範囲を渡す。
   - k = 2: 前ラウンドのレビュー所見（`NEEDS-CHANGES` の指摘全件）を渡し、対応を指示する。
   - 出力: 変更ファイル一覧、参照した設計書の節、既知の弱点・疑義。
2. **Reviewer ラウンド** — `estate-reviewer` を起動する。
   - 毎ラウンド新規起動する。
   - 入力: 変更ファイルのパス、引き渡しパッケージ原文。
   - 出力: VERDICT と所見一覧。
3. **判定分岐**:
   - `APPROVE` → ループ終了。ユーザーへ成果物とレビュー結果を提示。
   - `NEEDS-CHANGES` → k < 2 ならラウンド k+1 へ（Builder に差し戻す）。
   - `BLOCK` → ループを終了し、所見全文をユーザーへ提示して人間の判断を仰ぐ。

### 終了条件

- `APPROVE` に到達、`BLOCK`、または最大2ラウンドに達する。
- 2ラウンドで `NEEDS-CHANGES` のままの場合、その旨と残存する所見をユーザーに報告して終了する（無理に通さない）。

## オーケストレータ（呼び出し元）の心得

- Builder の成果物や Reviewer の所見を、要約・改変してから相手に渡さない（伝書鳩に徹する）。
- 自分で修正を行わない。修正は Builder ラウンドで行う。
- Builder に Reviewer を起動させない、または Reviewer の判定として扱わない（レビューの独立性を保つ）。

## 使わなくてよい場面

- ドキュメントのみの変更、設定ファイルのみの変更
- スクレイパー/クローラー/通知/DBスキーマに関わらない軽微な変更（分析スクリプトの微修正等）— この場合は `estate-builder` を直接使うか、ユーザーが直接作業してよい
