# コード追加時の TDD ルール

## 原則

`src/` 配下にコードを新規追加・修正する作業では、TDD（テスト駆動開発）の手順に従うこと。

## 手順

1. 実装前に、対象の振る舞いを検証する失敗するテストを先に書く（RED）
2. テストを実行し、失敗することを確認する
3. テストを通す最小限の実装を行う（GREEN）
4. リファクタリングする（IMPROVE）— 既存テストが green のまま保たれることを確認する
5. カバレッジを確認する（`pytest --cov=src --cov-report=term-missing`）

## 適用対象

- `src/` 配下の新規ファイル追加
- `src/` 配下の既存関数・クラスの修正（バグ修正・リファクタ含む）
- テストを伴わないコード追加は行わない

## 除外

- ドキュメント（設計書等）や設定ファイルのみの変更
- テストコード自体の修正

## 検証手段が使えない場合

テストランナーが実行できない、依存パッケージが無い等で検証できない場合、その事実を隠さない。試みたコマンドと発生したエラーを報告に明記し、当該変更は「未検証」として扱う。実行していないのに GREEN・カバレッジ達成を主張しない。
